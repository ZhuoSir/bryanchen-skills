# 产物模板（四个文件 + .specrc.yml）

创建 `specs/{YYYYMMDD}_{功能名}/` 时按以下模板初始化。`<>` 为占位说明，落盘时替换或删除。

---

## .specrc.yml（项目根，Phase 0 首次探测后经用户确认写入）

```yaml
# .specrc.yml —— bryanchen-spec 规范源路由表（团队共享，进 git）
# 源取值: global | file:<相对路径> | skill:<skill名> | none
domains:
  code-backend:   <global|file:...|skill:...|none>
  code-frontend:  <...>
  api-design:     <...>
  database:       <...>
  git-workflow:   global
  versioning:     global
project_files:
  - AGENTS.md      # 存在才列；永远生效，优先级最高
```

## requirements.md

```markdown
> 版本: v0.1.0 | 状态: 草稿 | 更新: <YYYY-MM-DD>

# 需求规格：<功能名>

## 背景与目标
<为什么做；解决谁的什么问题；成功长什么样（可度量的结果）>

## 需求条款

### R-01 <需求短标题>
<WHEN/IF/WHERE/WHILE 触发条件>,
系统 SHALL <可观察行为>。
<补充约束：量化指标、边界值。不写实现细节。>

#### 验收场景
- **GIVEN** <前置状态>
  **WHEN** <操作/事件>
  **THEN** <可观察结果>
- **GIVEN** <异常/边界前置>
  **WHEN** <操作>
  **THEN** <结果>

### R-02 ...

## Non-goals（范围外）
- <明确不做什么，防范围蔓延>

## 我正在做的假设
1. <假设内容>（如不成立请现在指出，否则按此执行）
2. ...

## 待确认问题
- <阻塞性问题列这里并停住等答复；没有则写「无」>
```

## checklist.md（releases/vX.Y.Z/，M4 前人工勾选）

```markdown
# vX.Y.Z 发版检查单

## 产物完整性
- [ ] sql/ 文件数 = MILESTONE.md 登记数，rollback 一一配对
- [ ] 每个 SQL 文件头注释块完整（版本/序号/来源/可重入/回滚）
- [ ] config/changes.md 覆盖全部配置项（与各 spec artifacts.md 核对）
- [ ] RELEASE-NOTES.md / UPGRADE.md 已评审
- [ ] **变更↔断言配对表**：本版每个触碰共享面的变更，项目回归载体
      （verify 脚本/测试套件）有对应新或改断言，逐变更列断言编号；
      无配对 = M4 不过（防「新规则没配新断言，旧行为悄悄死掉」）

## 演练（必须真做，不许纸面勾选）
- [ ] 演练环境按 UPGRADE.md 完整走一遍：SQL 全执行、配置全应用
- [ ] 演练后核心功能验证通过（记录验证人与时间）
- [ ] 演练中回滚步骤也走过一次
- [ ] 演练发现的问题已修复并更新 UPGRADE.md

## 发布（顺序即纪律：落账 → 四步核验 → tag → 合 main → 复核）
- [ ] **Bug 台账三步对账完成**：本版 `Bug:` footer 与台账互核无差、全部翻「已发布(vX.Y.Z)」、
      merge-base 反核通过、「未随本版清单」已报并确认去向
- [ ] **发版落账批处理完成**（M4 步3）：MILESTONE 各 spec 翻**终态「已发布」**（禁停"已合并"）、
      状态头/汇总进度/version.md/CHANGELOG 全部写齐
- [ ] **四步核验绿**（M4 步4）：逐条 grep 落账回验 ✓ + 里程碑审计复跑全绿 ✓ + 工作树干净已 commit ✓
- [ ] git tag -a vX.Y.Z 打在**落账后的 tip** 上（message 含 spec 清单）
- [ ] 合并 main（口令确认后）：`git diff vX.Y.Z main -- releases/…/ version.md` **为空**（非空=账滞后事故）
- [ ] push（口令）+ 远端复核（ls-remote 对齐 + 远端 MILESTONE 抽看终态）
```
