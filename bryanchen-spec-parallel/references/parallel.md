# 并行 spec 模型（worktree + 账房）——本 skill 核心 v13.2

**总原则**：分支隔离逻辑，worktree 隔离物理，**串行隔离账**——全局账唯一写入动作「落账」
（账房锁串行化），**空间凭证与编号同点发放**；并行放到写码为止，合并永远排队。
单人 = 兄弟清单为空的退化情形，拓扑无特例。

## 一、拓扑与账房

- 主目录永远检出现在的在途版本分支 =「账房」：挂接/落账/合并回/M2-M4/init 只在这里发生，
  一律先持账房锁。
- **账房锁** `specs/_project/.ledger.lock`（持有者+时间戳）。<2h 排队；>2h 用户裁决接管。
  账房禁 `git add -A`，只许列路径清单（锁内完成编辑+提交）。
- 活跃 spec 清单 = `git worktree list` + `specs/_project/fragments/`（机械事实）。
- **引擎互斥（启动步骤 0）**：`.specrc.yml` 声明 `spec_engine` 且 ≠ 本 skill → 拒执提示换版；
  **缺声明不拒执**（视为自身，兼容存量；由并行版运行时补写）。
- 跨版本并行禁止；并行仅限同一在途版本下互相独立的 spec（依赖即串行）；软上限 2。

## 二、台账碎片（全局账唯一写入通道，Phase 0 起全程）

碎片 `specs/_project/fragments/<spec名>.md`，**协议：只许 append（>>），禁 read-modify-write**；
**由 owner 在自己的落账批提交，账房不代提交他人碎片**（夹带事故 `2671ae5` 教训）。行型：

```
挂接意图: | 新版意图: | 空间申报: errno/SQL/schema/端口/键段 需求描述
共享面申报: <对象> 意图 <描述>        ← 含「申报修正:」变体（改判后必须追，落账以其为准）
BUG候选: | L候选: | BL候选: | 占用: <测试|建表|端口|构建>
行为增量: <域> 行为 A→B（来源 <spec>@vX.Y.Z）
账目变更: profile §<节> → <内容>
```

**落账**（主账唯一写入点，账房锁内）：读碎片 → **按全局现值分配 BL/BUG/L 编号** →
写各主账 → 碎片行尾「已落账→编号」→ **同步记录权威副本指纹**（§2.5）→
  所有被改主账跑 `mdtable_check.py`（落账全是表格手术，SKILL §0.8 表格闸）。
- **两类落账**：合并落账（大批，编号转正/终态）＋ **进度小落账**（MILESTONE 本行进展、
  候选转正号、profile 口径——owner 自持锁即落，每任务组一次，不等合并；治看板滞后与
  「文档引用不了编号」两副作用）。正反例：owner 自落=正例；行停「立项中」实际已 7/16=反例。
- 落账回填必记「取自 spec 哪个版本」；与 owner 最新「申报修正」冲突时以修正为准。

### 2.5 权威副本：⚑ 指针 + sha256 指纹 + 后果
- 挂接落账批同时在**账房** spec changelog 头写 ⚑ 指针行（权威=wt-x@feature/x；本份=只读快照，
  **合并时以树内覆盖**——无「择机快进」判断题）。
- 落账批记录权威副本 hash → `specs/_project/.authoritative/<spec>.sha256`。
  **勾选归一化**：tasks.md 的 `- [ ]`/`- [x]`/`- [X]`/`- [ x ]` 归一 `- [.]` 后再哈希；
  任务描述/条目增删仍触发失效（否则每勾一次就误报，指纹会被当噪音关掉）。
- **漂移=硬停**：审计/合并前 `shasum -c` 不符 → 以树内重出快照＋记原因与责任批次，处置完才继续。
- 阅读规则：并行期读 spec 文档 = 读 worktree。

## 三、空间凭证（与编号同源，挂接落账即发放——**必须早于任何写码**）

- 账房落账批为 spec 划段，写入 `releases/vX.Y.Z/SHARED.md`「命名空间」节：
  admin-errno 段 / wx-errno 段 / SQL 序号段 / schema 名 `demo_<slug>` / 端口偏移 / 测试键段。
  **spec 写码只准用段内取值**；段满向账房申请扩段（落账批动作）。
- **预检脚本**（skill 给参数化模板，项目实体化 `verify/precheck.sh`）**三处必跑**：
  确认② ＋ 每次落账 ＋ M3——同一份脚本，杜绝「靠自觉」：
  `merge-base` 两分支改动文件集 ∩ ＋ **枚举新增 value diff** ＋ SQL 序号 diff → 冲突清单。
- **确认② 硬门**：矩阵对象 ∩ 或 空间段 ∩ ≠ ∅ → 仲裁（结论不一致硬停呈报，裁决入
  SHARED「版本级结论」双方 follow）。
- **合并后回归必含「值唯一性断言」**：共享枚举/常量类（errno 等）合并后断言全量 value 唯一——
  git 能报文件冲突，但冲突解决「都保留」后的**同号不同义**测试全用符号常量抓不到，只有此断言能抓。

## 四、六纪律

### ⓪ 建树五查（确认③后、worktree add 前，全绿才建）
```
1) 挂接意图已落账（含空间凭证与指纹基线已发） 2) 账房 git status 空（仅自有碎片 dirty 除外）
3) 账房 HEAD 在版本分支     4) profile §worktree兼容 非空（空→先演练）
5) 账房与树内双侧 ⚑ 指针行就位
```

### ① 物理
写码/构建/验收都在自己 worktree；不进兄弟树；进账房前置 = 它干净。文档权威副本在树内。
**Phase 0~3 文档与全局账是账房行为**：写第一份 spec 文档前先验 HEAD 在版本分支、工作区干净
——账房恒在版本分支上，所以并行模式天然免疫「文档 hostage 在施工分支」；单线程项目同理
（git-workflow §三 文档栖身铁律）。

### ② 账
见 §二（碎片全程 + owner 自提 + append 协议）。

### ③ 合并五步（先入后出→合回→落账→回归→收尾）
```
1) 兄弟已合入？先入：树内 git merge <版本分支> → garden 解冲突、按对方改动复核自己断言、全绿
2) 回账房（持锁）merge --no-ff feature/<名>
3) 落账：碎片批量编号入账 + **BL 联动检查**（本 spec 对应 BL 仍待办→纠错翻已立项；
   随版发布→已交付，SKILL 待办节锚点②）+ 树内断言**单向同步**进账房 verify/（超集规则，禁两边各改）
4) 版本分支全量回归：法定载体=账房 releases/vX.Y.Z/verify/（-Dspec=<slug> 选层）——
   含**值唯一性断言**；红 = 只许 revert -m 1 冲销（reset 禁），碎片未落状态自洽
5) 收尾：worktree remove → branch -d → 放锁 → 回执三行（合并✓落账✓移除✓）
```

### ④ 环境：占用表与 .accept 双写
- 占用互斥资源（验收栈/dev server/**共享 DB 写**/共享缓存构建）前：`.accept`（spec+时间+用途）
  双写自己树根 + `specs/_project/.locks/<spec>.accept`（对未建树会话可见）。<2h 排队；>2h 裁决接管。
- **取锁核查的判据 = 占用表**：落账批核对「活跃 spec ∪ .locks/ 目录 ∪ 碎片『占用:』行」三方一致，
  缺锁即报「占用未声明」。
- **数据隔离默认 schema-per-spec**（`demo_<slug>`）；harness 默认 schema **不得是任何 spec 私库**
  （默认 `demo`），私有库经 `-Ddts.test.schema=` 注入（一张嘴一个碗的教训）。
- **known-failures 基线** `releases/vX.Y.Z/known-failures.md`（账房维护、全分支共读）：
  既有失败清单入版本级档案，「新红=本分支引入」判定基准；**覆盖缺口（测不了/没测的）逐条记
  owner＋回补时点**，M3 审计核对。
- **环境快照带时间戳**：profile 环境节每行「事实@日期」；审计比对不一致 → 广播受影响 spec
  走「外部事实同步」PATCH（并行期固定开销，如实记账不装消失）。

### ⑤ 互知
启动摘要固定行：兄弟清单（worktree+spec+涉及模块）＋账房锁持有者＋未落账碎片数。

## 五、独立评审（fresh-context reviewer）

**条件触发**（仪式配得上赌注）：触及 ≥2 共享面 / 动钱或权限 / ≥8 任务 → **必做**：确认②呈报前
＋先入后合回前，各派一个**不继承施工上下文**的 reviewer（subagent）读三份文档＋diff，
问题清单随呈报附上；纯 PATCH 无行为变更 → 跳过。**reviewer 只出问题清单，VERDICT 裁定权在人。**

## 六、行为账 `specs/_project/behavior.md`（系统现状的受控真相）

- 来源=碎片「行为增量:」行，落账聚合；**整节替换不追加**——被触碰的域以当前真相重写整节，
  未触碰域不动；节头「截至 vX.Y.Z ← spec 目录」血缘必留（防变成会腐烂的 wiki）。
- 治理的问题：N 个 spec 之后没人知道「系统现在怎么运作」；init 反回填哲学不破——只记被改过的域。

## 七、轻确认纪律（配合 versioning §1.2.1）

呈报格式固定三行「原文X → 新文Y ｜ 原因一句话」；changelog 知悉记录附 diff 摘要锚；
**先呈报后记录——未呈报的改动不得预记知悉人**（「从『继续』推断知悉」自曝教训）。

## 八、worktree 兼容演练（首次启用必做，五查④强制）
- cache_root 绝对化（mvn repo local / pnpm store 指 repo 外共享）；**跨模块测试必 `-am`** 与
  共享 local repo 的坑写进 profile；
- 排查 `../`、symlink、bind mount、**换行符**（CRLF 项目脚本按字节读写；`core.autocrlf` 行为先测）；
- schema 克隆脚本内含三教训：`--default-character-set=utf8mb4`／容器 `--restart unless-stopped`／
  就绪判定用**最终凭据真实查询**而非 ping；磁盘基线记录。

## 九、并行期 push 与 M4
- push 前披露 `git log <remote>..<版本分支> --oneline` 全量（推的人对全部提交负责）。
- M4 发版照常走 v10.x（账先于 tag＋四步核验），判据表含空间/指纹/覆盖缺口/环境新鲜四行。
